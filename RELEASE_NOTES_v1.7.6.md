# Release Notes v1.7.6

IRK Capture v1.7.6 makes clearing pairings complete and fixes several problems found in a code review. Refresh BLE Identity and Forget All Bonds now fully remove each paired device, and both report clearly when cleanup is incomplete. Status reports `failed` when pairing times out. Turning advertising off always stops the radio, and every capture fires its own Home Assistant event. The wizard login is harder to brute-force, and the wizard rejects malformed commands and credentials that are too long to work.

## What's new for you

- **Clearing pairings is complete.** Refresh BLE Identity and Forget All Bonds used to delete the stored pairings but leave each device's identity key in the list Bluetooth uses to recognise private addresses. A cleared phone was still recognised the moment it reconnected (the log showed its real identity in the `peer id` line) until the ESP32 rebooted. Cleanup now resets the entire resolving list while preserving the ESP32's own identity key, checks that operation's result, and clears the bond store. This also removes leftover keys whose bond records were already deleted. Every retry checks both operations, even when the bond store is empty.
- **Refresh BLE Identity is more reliable.** It now checks with Bluetooth that advertising has actually stopped before clearing pairings and changing the address, and retries the stop if it doesn't take. Before, one failed stop could make the address change fail, or let pairings be cleared while the ESP32 was still advertising. The log now shows a single "Advertising stopped" line per refresh instead of two.
- **Turning advertising off always works.** If a restart of advertising failed partway, the ESP32 could believe advertising was off while the old advertisement kept running. Turning the BLE Advertising switch off then did nothing, and the device stayed visible. The ESP32 now asks Bluetooth whether it is really advertising, so off always stops the radio, and a failed restart is retried.
- **Every capture fires its own event.** If two devices were captured before the ESP32's main loop caught up (for example during a Wi-Fi or Home Assistant stall), only the second fired `esphome.irk_captured`. The first was in the capture history but never reached your automations. Each capture now fires its own event, in order, with the IRK and MAC sensors already showing that capture.
- **Incomplete cleanup is reported, with the right advice.** If Refresh BLE Identity changes the address but cleanup fails, the wizard reports which part failed: bond storage, identity keys, or both. Press Forget All Bonds to retry. If identity-key cleanup keeps failing, restart the ESP32. A storage failure is reported separately because builds with persistent bond storage may retain those records across a restart.
- **Pairing timeouts show `failed`.** When a device connects but doesn't finish pairing (no encryption after 20 seconds, or no result after 90 seconds), Status now shows `failed` for a few seconds before returning to `advertising`. It used to go straight back to `advertising`, which made a stalled pairing look like nothing had happened. A timeout never replaces a key the connection already captured.
- **Disconnecting after a capture can't hit the wrong device.** After a capture, the ESP32 disconnects the device it captured from. That disconnect now runs on the Bluetooth task, right after checking it's still the same connection. Before, a device that reconnected within a fraction of a second could be disconnected instead.

There are no new entities, options or Status values.

### Wizard

- **The login lockout can't be bypassed.** Someone guessing passwords from five or more network addresses could reset the failed-login count on every attempt and never be locked out. A recent failed login now stays counted until that address has been idle for the full lockout period. While an attack from many addresses is under way, a new address shares the overflow limit with them, so you might be locked out briefly too.
- **Malformed commands are rejected.** The wizard used to act on a command whose JSON was truncated or invalid after the part it read. It now checks the whole command first. This only affects scripts that send the wizard commands directly. The page itself always sends valid JSON.
- **Credentials that can't work are caught when you build.** Username and password together are limited to 185 characters, because a longer pair produces a login header the ESP32 rejects, so you could never sign in. The username also can't contain `:`, which HTTP Basic authentication uses as its separator. Both now cause a configuration error instead of firmware you can't log in to.

## Upgrading

- **Rebuild as usual.** Devices that track `main` pick up this version on their next build.
- **No YAML changes are needed,** unless your wizard username contains `:` or your username and password together exceed 185 characters. The build then stops with an error that says which, and you can change them in `secrets.yaml`.
- **Home Assistant automations:** Status can now show `failed` after a pairing timeout. If an automation treats `failed` as an encryption error only, it now fires for timeouts too. After a stall, an `esphome.irk_captured` automation can now receive several events in quick succession, one per capture, where it used to receive only the last.

## For developers

- `clear_bonds_and_resolving_list()` in `irk_capture_history.cpp` reapplies a copy of the current local IRK with `ble_hs_pvcy_set_our_irk()`, which resets the complete resolving list, then calls `ble_store_clear()`. Both return codes are retained as `resolving_rc` and `store_rc` in `BondCleanupResult`. Unlike `ble_gap_unpair()`, the privacy reset propagates controller cleanup failures. With host-based privacy (`CONFIG_BT_NIMBLE_HOST_BASED_PRIVACY`, ESP32 only, off by default) the list is cleared in software and cannot fail, so `resolving_rc` is always 0 there. It runs on every request, including an empty-store retry, so orphaned resolving keys cannot produce false success. The two NimBLE privacy functions are exported SDK symbols with private header declarations; the adapter declarations are confined to this file and require firmware build-matrix coverage when changing SDK versions. The boot-time clear still uses `ble_store_clear()` because the resolving list is empty at boot.
- `IdentityRefreshState` gains `PARTIAL`, exposed as `identity_refresh.state: "partial"`. Its `cleanup_reason` gives the same specific recovery advice as Forget All Bonds; a new refresh clears the old reason.
- `handle_mac_rotation_()` no longer assumes the stop issued by `request_mac_rotation_()` worked. A new `mac_rotation_prepared_` flag keeps it retrying `stop_advertising()` until the stop is verified, sharing the rotation's retry budget, before it clears bonds. `loop()` retries a stop only when the advertising intent is off, and a rotation keeps it on, so the rotation has to own this retry.
- `advertising_` now follows `ble_gap_adv_active()` instead of return codes. `start_advertising()` caches the actual GAP state after a start, including a failed one, and if the defensive stop leaves the old advertisement running it reports a "stop before restart" failure without rewriting the name or payload. `stop_advertising()` returns `bool`: true only after it confirmed GAP is inactive while holding `ble_op_mutex_`, false on a lock timeout, a host reset or a stop that didn't take (which also arms `adv_stop_retry_time_`). It skips the HCI stop and the "Advertising stopped" log when GAP is already idle. The rotation uses that return value instead of `!advertising_`. `set_advertising_requested(false)` verifies GAP whenever the host is synced, `loop()` keeps retrying an OFF stop while `adv_stop_retry_time_` is armed, and the scheduled restart in `loop()` no longer requires `!advertising_`.
- `on_capture` delivery is separate from the displayed result. `publish_irk_to_sensors()` queues each accepted capture in `pending_capture_events_` (up to `CAPTURE_EVENT_CAPACITY`, 32) when a trigger is registered, and `flush_pending_publishes_()` drains the queue in order, publishing each event's IRK, MAC and `captured` Status before its triggers. A full queue keeps the queued events, counts the rest in `pending_capture_event_drops_` and logs an error; the latest result is republished afterwards if it differs from the last delivered event. `fired_capture_sequence_` is gone.
- `terminate_bounded_()` now takes the connection generation and only records the request. `handle_pending_termination_()` runs on the NimBLE task via the existing worker event, revalidates `connected_`, `conn_handle_` and `connection_generation_`, and then calls `ble_gap_terminate()`. Connect and disconnect callbacks run on the same task, so a reused handle can't slip in between the check and the call. If `ble_op_mutex_` is busy, it logs once per pending disconnect (`pending_terminate_busy_logged_`) and retries on the next worker wake-up without blocking the host. The pairing timeout remains the fallback.
- `handle_connection_timeout_()` now calls `report_capture_failure_()`. That function also checks that the generation is still current, and it records `failed_generation_` so each connection reports at most once.
- `ClientThrottles` no longer evicts a slot with recent failures. A slot's failures are forgotten only after it has been idle for `AuthThrottle::LOCKOUT_MS`.
- `json_skip_value()` is now a real validator, covering objects, arrays, strings, literals and numbers, with nesting limited to 16. `json_find_value_start()` validates the whole body, rejects trailing data, and rejects a command key that appears twice.
- `validate_auth_config()` in `irk_wizard/__init__.py` checks the Base64 header length (`6 + 4 * ceil((user + 1 + password) / 3)` ≤ 256) and rejects `:` in the username.
- Helpers used by a single file moved out of `irk_capture_internal.h`: `io_cap_str`, `key_dist_str` and `log_sm_config` into `irk_capture_ble.cpp`, and `log_conn_params` and `log_sec_state` into `irk_capture_gap.cpp`. `log_sm_config` is now an ordinary function declared in the header. The GATT UUIDs moved into the new `irk_capture_gatt.h`, which only the GATT registration, advertising and GAP files include.
- Single-peer deletion after an encryption failure, a timeout or a repeat-pairing request still uses `ble_store_util_delete_peer()`. Its resolving-list behavior depends on the SDK. Refresh BLE Identity and Forget All Bonds now explicitly clear the full list, including any entries those paths leave behind.
